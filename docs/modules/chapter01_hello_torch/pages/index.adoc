== 1.1 头文件与命名空间

整本书里主要用到三个头文件：

[source,cpp]
----
#include <torch/cuda.h>
#include <torch/torch.h>
#include <c10/util/Optional.h>
----

* `torch/torch.h` —— _总头文件_，包含张量、nn 模块、优化器、序列化等 _绝大部分_ C++ API。
* `torch/cuda.h` —— 提供 `torch::cuda::is_available()`、`is_bf16_supported()` 等运行时检测。
* `c10/util/Optional.h` —— 提供 `c10::optional<T>`，相当于 `std::optional` 的早年代替品。

随用到随引入的还有：

[options="header",cols="2,4"]
|===
|头文件 |出现处（章节）

| `<torch/serialize.h>`         | `torch::save / torch::load`（[ch03]/[ch04] 模型保存）
| `<torch/script.h>`            | ch02 中用 TorchScript 包装自己的 tokenizer / dataloader（可选）
| `<torch/optim/adamw.h>`       | AdamW 显式构造（[ch07]）
| `<torch/jit.h>`               | `torch::jit::load`（IF 版本 / `gpt-toolcall` 中加载 HF 模型）
| `<torch/nn/parallel/...>`     | 数据并行（[ch05] 配 `DataParallel`，chG 的 `DistributedDataParallel`）
| `<torch/csrc/api/include/torch/autograd.h>` | `torch::NoGradGuard`（[chD] / [chG]）
|===

== 1.2 Device：CPU / CUDA 切换

后续章节每个 `main.cpp` 几乎都按以下固定模式处理 device：

[source,cpp]
----
torch::Device device = torch::cuda::is_available()
                           ? torch::Device(torch::kCUDA)
                           : torch::Device(torch::kCPU);
model->to(device);                              // 把模型参数 / buffer 全部搬到 device 上
auto x = torch::randn({2, 3}).to(device);        // 输入张量也搬到 device
----

要点：

* `torch::Device` 是一个轻量句柄，复制无开销。
* `kCPU` / `kCUDA` 是枚举值，相当于 `torch::Device::Type::CPU / CUDA`。
* **必须**对 `model` 和 `input` 做同样的 `.to(device)`，否则会触发 `Expected all tensors to be on the same device` 错误（本章 demo 实战已踩到）。
* 教学与书中复现脚本里几乎都额外关 TF32，保证与 Python `float32` 同精度：
+
[source,cpp]
----
at::globalContext().setAllowTF32CuBLAS(false);
----

== 1.3 Tensor 工厂函数

=== 1.3.1 由数据直接构造

[source,cpp]
----
auto x = torch::tensor({{1.0f, 2.0f, 3.0f},
                        {4.0f, 5.0f, 6.0f}});        // 自动推断 (2,3) float32
auto ids = torch::tensor(std::vector<int64_t>{101, 102, 103}, torch::kLong);
----

`torch::tensor(initializer_list|std::vector, dtype=optional)` 接收具体的数值。
注意：**索引型张量必须为 `kLong`**（Embedding 的输入、attention 的 mask、Tokenizer 输出都是 `kLong`）。

=== 1.3.2 形状 + 默认值的工厂

[options="header",cols="2,5"]
|===
|函数 |用途与示例

|`torch::empty(sizes, opts)`  |不初始化（用于需要"立刻覆盖"的占位张量）
|`torch::zeros(sizes, opts)`  |全 0：bias 初始化、mask、padding
|`torch::ones(sizes, opts)`   |全 1：广播型常量
|`torch::full(sizes, value)`  |填常量值
|`torch::arange(start, end)`  |整型序列，常用于 `position_ids = torch::arange(0, seq_len)`
|`torch::rand(sizes)`         |`[0,1)` 均匀分布
|`torch::randn(sizes)`        |标准正态分布：权重初始化的最爱
|===

=== 1.3.3 从裸指针构造

[source,cpp]
----
auto t = torch::from_blob(ptr, {B, H, D}, torch::kFloat);
----

`from_blob` 不会复制数据——非常适合 chG 自回归推理时复用 CPU 端的 KV cache 内存。
**注意**：所有权仍属于调用方；转 `to/clone` 才会被 LibTorch 接管。

== 1.5 形状变换：`reshape / view / transpose / permute`

[source,cpp]
----
auto a = torch::arange(12, torch::kFloat).reshape({3, 4});   // (3,4)
auto b = a.transpose(0, 1);                                  // (4,3)  view
auto c = a.permute({1, 0});                                  // (4,3)  view
auto d = a.view({-1});                                       // 自动推维度
auto e = a.unsqueeze(0);                                     // 加一维
auto f = e.squeeze(0);                                       // 去一维
auto g = a.flatten(0, 1);                                    // 合并若干连续维
----

要点：

* `view` 与 `reshape` 类似，但 `view` 要求张量 **连续**（`is_contiguous()==true`）；
  在做完 `transpose / permute` 后想继续 `view`，必须先 `.contiguous()`。
* `transpose(d1, d2)` 只交换两个轴，是便宜的视图；`permute({...})` 可以任意重排轴序，常用在多头注意力中：
+
[source,cpp]
----
// (B, H, T, D) 多头重排为 (B, T, H, D)
auto y = x.transpose(1, 2);                       // (B, T, H, D)
----

== 1.6 张量运算

=== 1.6.1 矩阵与元素运算

[source,cpp]
----
auto y = x.matmul(w);                          // @ → 与 np.matmul 语义一致
auto z = x.mul(y);   // 或 x * y              // 逐元素
auto z = x.add(y);   // 或 x + y
auto z = x - y;
auto z = x.pow(2);                             // x^2
----

`matmul` 在 2D 是 `x @ y`，在 3D+ 是按最后两维做批量矩阵乘。`.bmm()` 显式表达 batch matmul。

=== 1.6.2 `softmax / masked_fill / argmax / topk`

[source,cpp]
----
auto p = torch::softmax(x, /*dim=*/-1);                                // 把最后维做成概率分布
auto m = x.masked_fill(mask == 0, -1e9);                               // padding / causal
auto k = x.argmax(/*dim=*/-1);                                         // 每行最大下标
auto v = std::get<0>(x.topk(/*k=*/2, /*dim=*/-1));                     // 每行 top-k（值）
----

* `masked_fill`：**整个 attention 都靠它**——pad 位 / 因果位 / 全 0 区间，都填 `-1e9` 后 `softmax` 就变 0。
* `topk` 返回 `std::tuple<Tensor, Tensor>`，分别是 (values, indices)。
* `argmax / topk` 在 `gpt-toolcall` / chG 自回归生成里用来选下一个 token id。

=== 1.6.3 拼接与堆叠

[source,cpp]
----
auto ab = torch::cat({a, b}, /*dim=*/0);        // 沿已有维度拼
auto st = torch::stack({a, b}, /*dim=*/0);      // 新增一维再叠
----

`ch06` 拼接上下文向量、`chE` LoRA 切分训练样本、`chG` 把多个候选回应的 logits 拼起来都用 `cat`。

== 1.7 自动求导（Autograd）

[source,cpp]
----
auto x = torch::tensor({1.0, 2.0, 3.0}, torch::kFloat).requires_grad_(true);
auto y = (x * x).sum();
y.backward();
std::cout << x.grad();                            // → [2, 4, 6]

{
    torch::NoGradGuard no_grad;                   // 关闭 autograd
    auto z = (x * 2).matmul(w);                   // 推理 / 评估
}
----

五件事非常常用：

* `.requires_grad_(true)` —— 让一个 `Tensor` 参与 autograd；
* `.detach()` —— 把变量从图中分离（保留数值，但不参与梯度传播）；
* `.set_requires_grad(false)` —— 冻结层（LoRA / phase 2 阶段冻结 base model）；
* `tensor.backward()` —— 反向求导（标量 → 直接调用；向量 → 通常先 `.sum()` 或传 `gradient=`）；
* `torch::NoGradGuard no_grad;` —— 在作用域内临时关闭 autograd，**推理与 unit test 必备**。

== 1.8 优化器：训练循环的"四步走"

后续每章都会按以下模板跑训练循环：

[source,cpp]
----
for (int epoch = 0; epoch < n_epochs; ++epoch) {
    for (auto& batch : loader) {
        batch.data = batch.data.to(device);
        batch.target = batch.target.to(device);

        opt.zero_grad();                                  // ① 清零
        auto logits = model->forward(batch.data);        // ② forward
        auto loss = torch::nn::functional::cross_entropy( // ③ 计算 loss
                          logits, batch.target);
        loss.backward();                                  // ④ 反向
        opt.step();                                       // ⑤ 更新
        // scheduler.step();                              // 可选：余弦退火
    }
}
----

最常见的两个优化器写法：

[source,cpp]
----
// AdamW：首选，权重衰减与梯度解耦，书里 gpt-pretrain / SFT 全用它
torch::optim::AdamW opt(
    model->parameters(),
    torch::optim::AdamWOptions(3e-4).betas({0.9, 0.95}).weight_decay(0.01));
----

[source,cpp]
----
// SGD：ch05 pretrain 也常写"warmup 期"的 torch::optim::SGD，
// 用来观察参数动量是否稳
torch::optim::SgdOptions sgd_opts(1e-2);
sgd_opts.momentum(0.9);
torch::optim::SGD sgd(model->parameters(), sgd_opts);
----

学习率的两种调整方式：

[source,cpp]
----
double lr = opt.param_groups().front().options().get_lr();   // 查
opt.param_groups().front().options().set_lr(1e-4);           // 改
// 多 param_group 时（如 LoRA），遍历 opt.param_groups() 各自 set_lr。
----

[NOTE]
====
`Optimizer` 类本身 _没有_ `get_lr/set_lr` 公共方法——
必须通过 `param_groups()[i].options()` 拿到 `OptimizerOptions` 后再调。
需要 `betas / weight_decay` 等具体字段时，再 `static_cast<AdamWOptions&>(options)` 即可。
====

== 1.9 nn::Module：自定义层的标准姿势

整个 `gpt-sft` 的所有自定义层（`LayerNorm`、`GELU`、`MultiHeadAttention`、`TransformerBlock`、`GPTModel` ……）都长这样：

[source,cpp]
----
class LayerNormImpl : public torch::nn::Module {
 public:
    explicit LayerNormImpl(int64_t emb_dim, double eps = 1e-5) {
        scale_ = register_parameter(
            "scale", torch::ones({emb_dim}));
        shift_ = register_parameter(
            "shift", torch::zeros({emb_dim}));
        eps_ = eps;
    }
    torch::Tensor forward(torch::Tensor x) {
        auto mean = x.mean(/*dim=*/-1, /*keepdim=*/true);
        auto var  = x.var (/*dim=*/-1, /*keepdim=*/true, /*unbiased=*/false);
        return (x - mean) / torch::sqrt(var + eps_) * scale_ + shift_;
    }
 private:
    torch::Tensor scale_, shift_;
    double eps_;
};
TORCH_MODULE(LayerNorm);   // 生成 class LayerNorm : ModuleHolder<LayerNormImpl>
----

要点：

* `*Impl` 类继承 `torch::nn::Module`；由 `TORCH_MODULE(LayerNorm)` 宏自动生成 `LayerNorm : ModuleHolder<LayerNormImpl>` 这个"指针包装类"——它**等价于 `shared_ptr<LayerNormImpl>`**，可以直接当指针用。
* 模块注册一律用：
** `register_module("name", sub_module_ptr)` —— 注册子模块 / 子层；
** `register_parameter("name", tensor)` —— 注册可训练参数；
** `register_buffer("name", tensor)` —— 注册随模型一起走的常量张量（不参与梯度，但 `.to(device)` 时会一起搬走）。
* `forward(Tensor)` 写计算；外部用 `model(x)` 或 `model->forward(x)` 都行。
* 子模块访问：`model->fc_->weight.sizes()` （`fc_` 是 `register_module` 返回的 `shared_ptr`）。
* `model->train();` / `model->eval();` 切换 Dropout / BN 等的运行模式。
* `model->to(device)` 一次性把"参数 + buffer + 子模块"全部搬到目标设备。
* **整个 `*Impl` 类 + `TORCH_MODULE(Name)` 必须放在全局命名空间**，不要放进匿名 namespace——否则 `torch::save / torch::load` 的 ADL 关联会断。

== 1.10 模型遍历

[source,cpp]
----
for (const auto& p : model->parameters())            // 抽象迭代器 → Tensor&
    std::cout << p.sizes() << "\n";

for (const auto& np : model->named_parameters(true))  // (name → Tensor)（递归）
    std::cout << np.key() << ": " << np.value().sizes() << "\n";

for (const auto& nm : model->named_modules())         // (name → Module)（递归）
    std::cout << nm.key() << "\n";
----

典型场景：

* `model->parameters()` —— 直接传给 `AdamW` / `SGD` 的优化器；
* `named_parameters(true)` —— **冻结/解冻某个模块**（LoRA）：
+
[source,cpp]
----
for (auto& np : model->named_parameters(true)) {
    if (np.key().find("lora_") == std::string::npos) {  // 不以 lora_ 开头的
        np.value().set_requires_grad(false);
    }
}
----
* `named_modules()` —— 给特定层打 hook、统计激活值、做量化感知。

== 1.11 损失与 functional

[source,cpp]
----
// 分类 / 语言模型的标配
auto loss = torch::nn::functional::cross_entropy(
    logits.reshape({-1, V}), targets.reshape({-1}));
// 对应 PyTorch nn.functional.cross_entropy(logits.view(-1, V), target.view(-1))
----

其它常用 functional：

* `mse_loss(input, target, c10::optional<int64_t> reduction)`
* `softmax(input, dim)` / `log_softmax(input, dim)`
* `relu(input, inplace=false)` / `gelu(input)`
* `dropout(input, p, training=true)`

如果想脱离 `functional` 命名空间直接调用，可以这样：

[source,cpp]
----
auto y = torch::softmax(logits, /*dim=*/-1);
auto y = torch::log_softmax(logits, /*dim=*/-1);
----

== 1.12 序列化：保存 / 加载整模型

[source,cpp]
----
{
    torch::NoGradGuard no_grad;                         // 保存时务必 no_grad
    torch::save(model, "model.pt");
}

auto model_loaded = LayerNorm(/*emb_dim=*/128);         // 用相同的 *Impl* 重新构造
torch::load(model_loaded, "model.pt");
----

* `torch::save / torch::load` 是 _整模型_ 的"傻瓜"序列化：自动递归所有注册过的 parameter / buffer / 子模块。
* 反序列化时 `*必须*` 用与保存时相同的 `*Impl` 类，否则会因缺少字段而抛异常。
* 这是 ch06 微调与 chG 推理入口处复现权重的方式。
* ch02 自己实现的 safetensors-like 路径用的是 `tensor.save(stream)` / `tensor.load(stream)`，但对模型对象请用 `torch::save / load`。

== 1.13 训练循环模板

后续章节所有训练脚本本质都是下面这段的拷贝：

[source,cpp]
----
int main() {
    torch::manual_seed(123);
    torch::Device device = torch::cuda::is_available() ? torch::kCUDA : torch::kCPU;

    Dataset dataset(/*...*/);
    DataLoader loader(dataset, /*batch_size=*/2, /*shuffle=*/true);

    auto model = GPTModel(/*cfg*/);
    model->to(device).train();

    auto opt = torch::optim::AdamW(
        model->parameters(),
        torch::optim::AdamWOptions(3e-4).betas({0.9, 0.95}).weight_decay(0.1));

    for (int epoch = 0; epoch < n_epochs; ++epoch) {
        for (auto& batch : *loader) {
            auto x = batch.data.to(device);
            auto y = batch.target.to(device);

            opt.zero_grad();
            auto loss = compute_loss(model, x, y);
            loss.backward();
            opt.step();
        }
    }
    torch::save(model, "out.pt");
}
----

== 1.14 `c10::optional` 与 `TensorOptions`

很多函数签名里的可选参数都用 `c10::optional<T>` 表示"传 = 启用 / 不传 = 关闭"：

[source,cpp]
----
c10::optional<int64_t> maybe_topk = c10::nullopt;        // 关闭
if (condition) maybe_topk = 50;
auto tk = maybe_topk.has_value() ? maybe_topk.value() : -1;
----

`TensorOptions` 用来一次性描述 dtype / device / requires_grad：

[source,cpp]
----
auto opts = torch::TensorOptions().dtype(torch::kFloat)
                                       .device(device)
                                       .requires_grad(true);
auto w = torch::randn({768, 4 * 768}, opts);
----

这套写法在 ch04 的 `MultiHeadAttention` / `FeedForward` 内部也常出现。

== 1.18 小结

阅读完本章后，应能：

* 不查文档写出 `torch::softmax(x, dim)`、`x.masked_fill(mask, -1e9)`、`tensor.to(device)`。
* 解释 `register_module` / `register_parameter` / `register_buffer` 的区别与适用场景。
* 把 `AdamWOptions(lr).betas(...).weight_decay(...)` 改成任意 `Optimizer` 同义写法。
* 用 `named_parameters(true)` 一行冻结 LoRA 之外的全部梯度。
* 在推理段正确处理 `NoGradGuard` 与 `model->eval()`。

完成 chapter01 的"前置知识练习"后，正式进入 chapter02。
