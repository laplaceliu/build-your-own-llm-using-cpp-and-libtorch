## 钩子

**LLM 不认识汉字，它只认识 0/1。**

那它怎么读懂「你好，世界」？

---

## 三层映射

```
"你好，世界"
   ↓  分词
["你", "好", "，", "世界"]
   ↓  编码
[1024, 5678, 89, 4321]      ← 每个 token 一个整数 ID
   ↓  嵌入
[[0.12, 0.34, ...], ...]   ← 每个 ID 变成 768 维向量
```

**LLM 只吃第三步的「向量」。**

---

## 为什么要分词？

直接按字符拆不行吗？

| 文本 | 字符数 | 词数（中文按词） |
|---|---|---|
| "你好世界" | 4 | 2 |
| "Hello World" | 11 | 2 |

**字符级的问题**：
- 序列太长，Transformer 计算量 O(n²) 爆炸
- 词汇表小但利用率低（多数语言字符上万）
- 训练数据稀疏

**词级的问题**：
- 词汇表巨大（中文至少 50 万）
- 没见过的词（OOV）处理不了

**token 级（折中）**：
- 词表适中（GPT-2 = 50,257）
- 高频词保留，低频词拆成 subword
- 频率驱动，统计最优

---

## 主流分词算法

| 算法 | 代表 | 特点 |
|---|---|---|
| **BPE** | GPT-2, RoBERTa | 字节级 + 贪心合并 |
| **WordPiece** | BERT | 类似 BPE，按似然选合并 |
| **Unigram** | T5, XLNet | 反向：从大词表往下砍 |
| **SentencePiece** | LLaMA, Mistral | 语言无关，BPE/Unigram 都可 |

本项目实现的是 **GPT-2 同款 BPE**。

---

## 一个例子

文本："The quick brown fox"

GPT-2 BPE 分词：
```
["The", " quick", " brown", " fox"]
→ [464, 2068, 7586, 21831]
```

文本："我不爱吃香菜"

GPT-2 BPE 分词（按字节）：
```
["\xe6", "\x88", "\x91", "不", "爱", "吃", "香", "菜"]
→ [161, 229, 76, 122, 225, 102, 165, 165]
```

中文字符一个 UTF-8 字节一个 token，所以中文比英文贵 3 倍。
