# E.1 LoRA 原理：低秩分解为什么有效

## 钩子

**355M 参数的模型微调，训练参数量可以降到 0.5M（0.14%）？**

LoRA：低秩适配，参数高效微调的事实标准。

---

## 核心思想

**假设**：权重更新矩阵 ΔW 是「低秩」的。

```
W ∈ R^(d × d)
ΔW ≈ A × B    A ∈ R^(d × r), B ∈ R^(r × d)
```

**参数量**：d² → 2 × d × r

**当 r << d**：参数急剧减少。

---

## 数字对比（GPT-2 medium）

| 层 | d | 全量 ΔW 参数量 | LoRA 参数量 (r=8) |
|---|---|---|---|
| Attention W_q | 1024 | 1.05M | 1024 × 8 × 2 = **16K** |
| FFN fc1 | 1024→4096 | 4.19M | (1024 + 4096) × 8 = **41K** |
| 单 Block | — | ~25M | ~150K |
| 24 Block | — | ~600M | **~3.5M** |

**0.6% 的参数量，覆盖全部注意力层**。

## LoRA 三个关键设计

### 1. 冻结原权重

```cpp
auto W = model.attn.W_q;  // [1024, 1024] 冻结
W.set_requires_grad(false);
```

### 2. 注入小矩阵

```cpp
auto A = torch::randn({1024, 8}) * 0.01;  // [d, r]
auto B = torch::zeros({8, 1024});         // [r, d]，初始化为 0
A.set_requires_grad(true);
B.set_requires_grad(true);
```

**A 用随机初始化，B 用零初始化**：训练开始时 ΔW = A×B = 0，模型输出不变。

### 3. 前向时相加

```cpp
torch::Tensor forward(torch::Tensor x) {
    auto base_out = x @ W.T;        // 原权重路径
    auto lora_out = (x @ A) @ B;    // LoRA 路径
    return base_out + lora_out * (alpha / r);
}
```

**alpha/r 是缩放因子**：通常 alpha = r 或 alpha = 2r。

---

## 为什么低秩就够？

### 数学直觉

ΔW 表示「任务需要的方向」，大量研究表明这个方向高度集中在低维子空间。

**类比**：在一个 1024 维的空间里，「学翻译」这个任务可能只需要 8 维的方向。

### 论文实验

LoRA 论文（Microsoft 2021）在 GPT-3 175B 上：
- r=4：性能 ≈ 全量微调
- r=8：性能 ≈ 全量微调
- r=64：性能 > 全量微调

**r=4 已经够用，r=8 是性价比甜点**。

---

## 4 个优势

| 优势 | 说明 |
|---|---|
| **省显存** | 优化器状态从 2×d² 降到 2×d×r |
| **训练快** | 计算量少，反向传播也快 |
| **多任务** | 同一 base 配不同 A/B 就能切换任务 |
| **无延迟** | 推理时合并到原权重，零开销 |

---

## 推理时合并

```cpp
// 训练完
auto W_merged = W + (A @ B) * (alpha / r);

// 保存 W_merged 替代 W
// 推理代码完全不变
```

**优势**：合并后的模型与原模型完全兼容，无需新推理代码。
