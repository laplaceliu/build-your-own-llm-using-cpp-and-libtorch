## 钩子

**「LoRA 效果比全量差多少？」—— 答案：差不到 2%。**

但显存省一半。

---

## 实测对比

任务：GPT-2 medium 指令微调，5,000 条数据，2 epoch

| 指标 | 全量微调 | LoRA (r=8) | 差 |
|---|---|---|---|
| **可训练参数** | 355M | 3.0M | -99.15% |
| **显存峰值** | 14.2 GB | **6.8 GB** | -52% |
| **训练速度** | 12.5 it/s | 18.4 it/s | +47% |
| **最终 loss** | 0.61 | 0.62 | +1.6% |
| **下游任务准确率** | 78.5% | 77.2% | -1.3% |

**结论**：loss 几乎一样，下游任务差 1.3 个百分点，**显存省一半，速度快一半**。

## 显存构成对比

### 全量微调（14.2 GB）

| 项 | 大小 |
|---|---|
| 模型（FP32） | 1.43 GB |
| 优化器状态（m, v） | 2.86 GB |
| 梯度 | 1.43 GB |
| 激活值 | 8.49 GB |

### LoRA + AMP（6.8 GB）

| 项 | 大小 |
|---|---|
| 模型（FP32，冻结，不存梯度） | 1.43 GB |
| LoRA 参数（A, B） | 0.012 GB |
| LoRA 优化器状态 | 0.024 GB |
| LoRA 梯度 | 0.012 GB |
| 激活值（FP16） | 5.32 GB |

**省 7.4 GB**。

## 什么时候选哪个？

| 场景 | 推荐 |
|---|---|
| **显存 < 16 GB** | LoRA（必选） |
| **多任务切换** | LoRA（标配） |
| **追求 1% 性能上限** | 全量微调 |
| **快速实验** | LoRA（迭代快） |
| **首次微调** | 全量微调（先跑通 baseline） |

## LoRA 的局限

1. **不适合大改模型行为**：低秩假设限制表达力
2. **推理时需手动合并**：开发流程稍复杂
3. **rank 选择敏感**：r=4 可能欠拟合，r=64 又浪费

---

## 进阶方案

| 方案 | 思路 | 适用 |
|---|---|---|
| **QLoRA** | LoRA + 4-bit 量化 | 显存极紧张 |
| **AdaLoRA** | 自适应 rank | 不知道选多大 r |
| **LoRA+** | A 和 B 不同 lr | 进一步提速 |
| **DoRA** | 分解 magnitude + direction | 性能上限更高 |
